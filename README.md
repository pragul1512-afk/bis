# BIS Setu — PC Full-Stack Hackathon Prototype

This version is designed for a **PC/desktop browser** and contains a real local Node.js REST API backend.

## Main stack

- Frontend: HTML + CSS + JavaScript
- Backend: Node.js + Express
- Storage: JSON files (easy to run, no database installation)
- Authentication: JWT
- File upload: Multer
- AI: optional OpenAI Responses API integration through server-side `fetch`
- Product verification: local demo data + adapter endpoint
- Semantic-style search: local relevance scoring over indexed demo documents

## Run

1. Install Node.js 20+.
2. Open this folder in VS Code.
3. Open terminal:
   ```bash
   npm install
   ```
4. Copy `.env.example` to `.env`.
5. Optional: add your OpenAI API key to `.env`.
6. Start:
   ```bash
   npm start
   ```
7. Open:
   `http://localhost:3000`

## Deploy with GitHub and Render

The repository includes a GitHub Actions workflow at
`.github/workflows/ci.yml`. It runs on pushes and pull requests, installs the
locked dependencies, checks the server syntax, and verifies `/api/health`.

To deploy the application:

1. Create a GitHub repository and push this project. Do not commit `.env`,
   `node_modules`, or `uploads`; they are excluded by `.gitignore`.
2. In Render, choose **New +** → **Blueprint** and select the repository.
   Render will use `render.yaml` and build the included `Dockerfile`.
3. Set `OPENAI_API_KEY` only if AI integration is required. `JWT_SECRET` is
   generated by the Render blueprint.
4. Use the health check URL `/api/health`. The application listens on the
   platform-provided `PORT` value.

The JSON database is stored under `data/`, and uploaded files are stored under
`uploads/`. The Render blueprint includes a persistent disk for `data/`.
This is suitable for a demo deployment; use a managed database and object
storage before production or horizontal scaling.

## Docker

Build and run locally:

```bash
docker build -t bis-setu .
docker run --rm -p 3000:3000 -e JWT_SECRET=replace-with-a-long-secret bis-setu
```

## API endpoints

### Auth
- POST `/api/auth/register`
- POST `/api/auth/login`
- GET `/api/auth/me`

### Dashboard
- GET `/api/dashboard`

### Products
- GET `/api/products`
- POST `/api/products/verify`

### Documents
- GET `/api/documents`
- POST `/api/documents/upload`
- GET `/api/documents/:id`
- GET `/api/documents/search?q=...`

### AI
- POST `/api/ai/chat`

### MSME certification
- GET `/api/certifications`
- POST `/api/certifications`
- PATCH `/api/certifications/:id`

### Certificates
- GET `/api/certificates`
- GET `/api/certificates/:id`

## Important hackathon note

The project intentionally labels verification and BIS records as demo data. Do **not** claim that this prototype is connected to an official BIS production database unless your team has an authorized BIS integration.

For a production system, replace the demo adapter with an authorized BIS service, add a real database, document extraction/OCR pipeline, vector database, secure secret management, rate limiting, audit logs and production authentication.
